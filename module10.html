SQL, Data Analytics & Visualization

From relational databases to actionable business intelligence

Module Overview

This week, we will explore how organizations use Structured Query Language (SQL), databases, data analytics, and visualization tools to transform raw business data into meaningful information that supports decision-making.

Students will gain hands-on experience using PostgreSQL and pgAdmin 4 to create and query databases. We will also explore how cloud databases and business intelligence platforms such as Tableau, Microsoft Power BI, and IBM Cognos support business performance analysis.

Our goal: Understand not just how to write SQL, but how data helps managers identify trends, evaluate performance, and make informed decisions.

Learning Objectives

  1. Explain the role of SQL and relational databases in MIS.
  2. Identify common data types and recognize data quality issues.
  3. Create and populate a PostgreSQL database using SQL.
  4. Write SQL queries using SELECT, WHERE, ORDER BY, GROUP BY, and understand JOIN.
  5. Use aggregate functions to analyze business information.
  6. Explain how cloud databases support organizational analytics.
  7. Export query results and use them in a visualization platform.
  8. Develop business insights and recommendations based on analyzed data.

Part 1: Understanding SQL & Business Analytics

SQL (Structured Query Language) is used to communicate with relational databases. Businesses use SQL to retrieve, filter, organize, and analyze information. For example, a retailer might ask:

  • Which products generate the most revenue?
  • What are total sales this month?
  • Which customers make the most purchases?
  • Which regions are performing best?

Part 3: Hands-On SQL Lab — Retail Sales Analysis

Scenario: MIS Retail Solutions, a fictional retailer, wants to analyze its transactions and identify its best-performing products.

Step 1: Create a database

  1. Launch pgAdmin 4 and connect to your local PostgreSQL server.
  2. Right-click Databases → Create → Database.
  3. Name the database mis_analytics and save.
  4. Select the new database and open Tools → Query Tool.

Step 2: Create the sales table

SQL — Create Table
CREATE TABLE sales (
    sale_id INTEGER PRIMARY KEY,
    product_name VARCHAR(100),
    category VARCHAR(50),
    quantity INTEGER,
    unit_price NUMERIC(10,2),
    sale_date DATE,
    region VARCHAR(50)
);

Step 4: Run five analytical queries

Query 1 — All Sales
SELECT * FROM sales;
Query 2 — Total Revenue
SELECT SUM(quantity * unit_price) AS total_revenue
FROM sales;
Query 3 — Revenue by Product
SELECT product_name,
       SUM(quantity * unit_price) AS revenue
FROM sales
GROUP BY product_name
ORDER BY revenue DESC;
Query 4 — Revenue by Region
SELECT region,
       SUM(quantity * unit_price) AS revenue
FROM sales
GROUP BY region
ORDER BY revenue DESC;
Query 5 — Transactions Over $1,000
SELECT product_name,
       quantity,
       quantity * unit_price AS transaction_total
FROM sales
WHERE quantity * unit_price > 1000
ORDER BY transaction_total DESC;

Part 4: Cloud-Based Databases

Organizations use cloud databases for remote access, centralized reporting, collaboration, and scalability. PostgreSQL can be hosted on providers such as Render, AWS, Azure, or Google Cloud.

Key concepts include database hostnames, ports, usernames, passwords, connection strings, access controls, and encrypted connections. Never publish database passwords or expose a database publicly without appropriate security controls.

Optional advanced activity: Deploy a PostgreSQL database on a cloud platform and connect using pgAdmin. This is not required for the introductory lab.

Part 5: Data Visualization & Dashboard Development

Students will transform SQL results into business charts. For the simplest workflow, run a query in pgAdmin, export the result grid to CSV, then import the CSV into Tableau or another approved tool. Alternatively, connect Tableau directly to PostgreSQL if the correct driver and connection permissions are available.

Required Dashboard Elements

  1. Revenue summary: A KPI or scorecard displaying $12,720 in total revenue.
  2. Product comparison: A bar chart of revenue by product.
  3. Regional comparison: A bar chart or other suitable chart showing revenue by region.
